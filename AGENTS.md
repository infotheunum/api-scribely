## Обязательный Git-flow

Этот процесс обязателен для любой задачи в репозитории.

1. Обновить ссылки на remote и начать работу только от свежего `origin/dev`.
2. Создать отдельную ветку `<type>/<short-name>`, где `type` — `feature`, `fix`, `chore`, `docs`, `refactor` или `test`.
3. Коммитить только изменения текущей задачи, запушить эту task-ветку и открыть PR с base `dev`.
4. Влить PR в `dev` только после успешного CI и разрешения конфликтов. Следующую задачу снова начинать от обновлённого `dev`.

Прямые commit, push и merge в `dev` или `main` запрещены. Force-push в них запрещён без исключений. `git push --force-with-lease` допустим только для собственной ещё не влитой task-ветки после rebase.

Обычные task-ветки никогда не создаются от `main` и никогда не вливаются прямо в `main`. Когда в `dev` накоплен готовый релиз, открыть отдельный PR `dev -> main` и влить его только после обязательных проверок.

Единственное исключение — аварийный `hotfix/*`: он создаётся от `main`, проходит PR в `main`, после чего изменение немедленно возвращается отдельным PR/back-merge `main -> dev`. Нельзя оставлять исправление только в `main`.

Dependabot и другие автоматические dependency-обновления должны использовать `target-branch: dev`. Для каждой автоматической ветки действуют те же CI и PR-требования.

Если рабочее дерево содержит посторонние изменения, не переносить и не удалять их: использовать отдельный worktree или остановиться и сообщить владельцу.

## Проверки

- Для Python-кода выполнить релевантные `ruff` и `pytest` через `uv`.
- Для конфигурации и документации выполнить как минимум `git diff --check`.
- Не обходить упавшие проверки и не ослаблять CI ради merge.
